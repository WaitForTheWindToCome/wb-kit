# 从想法到交付：一条完整闭环怎么走

以"**给结构校验器补回归测试**"为真实样例，展示每一步谁做、产物在哪、怎样才算通过。

## 角色分工

| 谁 | 做什么 |
|---|---|
| **你** | 随手丢想法；在门禁上审批；用看板看状态 |
| **AI agent（DSH / Claude Code）** | 清洗、初筛、调研、写方案与计划、派发任务、回收证据、独立验收、更新索引 |
| **看板 / sqlite** | 只读派生视图，永不承载真相 |

## 十步

| # | 步骤 | 产物 | 门禁 |
|---|---|---|---|
| 1 | 丢一句想法进 `00-inbox/` | 原始记录（append-only，永不改写） | — |
| 2 | 说"**清洗 inbox**" | `10-items/WB-YYYY-NNNN-*.md`：结构化 + 原文 + 事实/假设/待验证 | — |
| 3 | 说"**这值得做吗**" | 填 `triage`：七维度各带理由 + 六选一结论 | G1 进研究 |
| 4 | 说"**调研一下**" | `20-research/RS-*.md`：来源 + 已证实/推断/待验证 | — |
| 5 | 说"**出方案**" | `30-decisions/ADR-*.md`：备选、被放弃理由、重估触发条件 | **G2 立项（人批）** |
| 6 | 说"**出计划和验收标准**" | `40-plans/PLAN-*.md` + `ACC-*.md`（**先定验收再开发**） | **G3 进开发** |
| 7 | 说"**派给 Claude Code**" | `50-exec/EX-*.md` 任务包（自包含 + 写域 + 自证要求） | — |
| 8 | 收回结果 | 同文件回填：命令、退出码、原始输出、成本 | — |
| 9 | 说"**独立验收**" | `60-verify/VR-*.md`：逐条对照 ACC + 证据 + 复跑 | **G4 验收（人批）** |
| 10 | 说"**沉淀**" | `70-knowledge/KB-*.md`，条目进 `80-archive/` | G5 归档 |

## 手动建记录：`wb new`

不想让 agent 建、或想自己起个头：

```bash
wb new item "改一下对账口径"        # 自动编号 WB-2026-0007，套用模板，自带 frontmatter
wb new exec "跑一遍回归"            # EX-…
wb new decision "存储选型"          # ADR-…（全局四位）
```

**编号扫描整个 `workbench/`（含 .html 页面）**，所以不会与已有文件撞号，也不会出现"漏 frontmatter"。

## 三道命令（日常只需要这三条）

```bash
wb build          # 重建索引与看板
wb watch          # 常驻：文件一变就看板跟着变
wb check          # 结构校验 + 渲染自检 + 陈旧检测（CI 用的就是它）
```

## 几条硬规矩（不是为了好看，是为了能追责）

1. **原始输入永不改写** —— 清洗结果写新文件，条目里保留原文与哈希；
2. **没有证据不算完成** —— 命令 + 退出码 + 原始输出 + 产物哈希；**agent 的自述不是证据**；
3. **验收者 ≠ 执行者** —— 校验器会检查 `verifier == executor` 并报错；
4. **先验收标准后实现** —— 状态进到 `planned/ready/executing` 却缺 PLAN/ACC 会报警（确有特殊情况就写 `gate_exempt` 明示）；
5. **索引永不共享** —— 每台机器各自重建，看板页头显示源指纹；过期时 `wb check` 会告诉你。

## 第一次实测（10 分钟，零成本）

不用先想"我要测什么"，照下面念就行。

**准备**：双击 `start-dashboard.cmd` 打开看板（纯静态文件，不依赖任何服务）。看板开着，每一步都能看到卡片换列。

| 步骤 | 你对 agent 说 | 应得产物 | 看板变化 |
|---|---|---|---|
| 1 | "记一下：<任何一句不成熟的想法>" | `00-inbox/…md`（原文逐字） | 收件箱 +1 |
| 2 | "清洗 inbox" | `10-items/WB-…md`（结构化 + 原文 + 事实/假设/待验证 + 七维度初筛与结论） | 卡片移到「已初筛」 |
| 3 | "这个以前做过吗" | 命中历史的条目写进 `links.duplicates/related` | 卡片标签变化 |
| 4 | "这值得做吗 / 出个方案" | `20-research/RS-…md`、`30-decisions/ADR-…md`（**状态 proposed，等你批**） | 出现「待审批」列卡片 |
| 5 | 你回一句"批了" | ADR 转 accepted，条目转「已决策」 | 卡片换列 |
| 6 | "出计划和验收标准" | `40-plans/PLAN-…md` + `ACC-…md`（验收标准先于实现） | 出现「已计划」 |
| 7 | "派给 Claude Code"（可选，要花钱） | `50-exec/EX-…md` + 原始输出证据 | 出现「执行中」 |
| 8 | "验收一下" | `60-verify/VR-…md`：逐条对照 ACC + 证据 + 复跑 | 「验收中」→「已通过」 |
| 9 | "沉淀一下" | `70-knowledge/KB-…md`，条目归档 | 进「已归档」 |

## 怎么判断它真的在工作（而不是在演）

1. **看文件**：每一步都应有一个**带编号的 .md 文件**；没有文件 = 没发生。
2. **看理由**：初筛结论必须带理由（`triage.reason`），只给分数不算；
3. **看原文**：`10-items` 里必须逐字保留你最初的输入，被"优化改写"过就是违规；
4. **看证据**：任何"完成/通过"都要有命令、退出码、原始输出；**它自己的话不算证据**；
5. **跑校验**：`node workbench/index/validate.mjs` → 应为 0 错误；`node workbench/index/selftest.mjs` → 应报 `PASS 索引与源文件一致`。

**三个压力测试**（专门用来验证它不会骗你）：

- **拒绝测试**：丢一个明显低价值或已存在的问题 → 期望结论是 `archive` / `duplicate` **并给出理由**，而不是被"优化"成一件要做的事；
- **澄清测试**：丢一句极度模糊的话 → 期望它**先问澄清问题**，而不是直接开工；
- **抗自证测试**：问"这个做完了吗" → 期望它给**证据路径**，而不是"已完成"三个字。

## 常见问题

| 现象 | 原因 | 处理 |
|---|---|---|
| `WARN 索引落后于源文件` | 改了 md 没重建 | `wb build`（或开 `wb watch`） |
| `ERROR … ID 重复` | 两条记录用了同一个 ID | 改号并在 `log/` 记录 |
| `ERROR … links.related 指向不存在的 ID` | 链接写错或目标已删除 | 修正链接 |
| `WARN … status=accepted 但缺 PLAN/ACC` | 门禁未走 | 补 PLAN/ACC，或加 `gate_exempt` 说明 |
| `git pull` 后看板还是旧的 | 没装 hook | `git config core.hooksPath <workbench>/.githooks` |
