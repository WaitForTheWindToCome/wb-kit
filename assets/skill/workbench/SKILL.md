# Workbench 操作规程

**第 0 步永远是读 `workbench/SPEC.md`**（唯一权威）。本文件与 SPEC 冲突时，以 SPEC 为准。

## 你是谁
你是这套工作台的**唯一写入者**。人只审批和阅读。因此：写之前先想"这份内容属于哪个目录、哪个状态、要回链谁"。

## 工作方式（先读这四条，否则会犯最常见的错）

1. **先讲人话，再落台账**：任何一轮回复，先用 ≤10 行把结论讲清楚（不夹 frontmatter、ID、门禁术语），然后再决定要不要写记录。**把答案埋进台账格式里 = 没回答**。
2. **轻量模式**：纯咨询、问答、小改动（<30 分钟且无验收价值）**不建条目、不派发、不写 PLAN/ACC**。台账是给"需要被决策/被验收的事"用的。
3. **刹车条件**：连续 3 轮只有台账产出、没有实质结论，或用户问了 2 次仍没得到正面回答 → **立刻停下问用户**"我是不是跑偏了？你要的是哪个？"
4. **默认必须派发**：凡要动手改代码/产出工件的任务，**默认派发给编程 agent（Claude Code）并由非执行者验收**；只有用户明确说"你自己做"、或确实 <30 分钟且无验收价值时才自己做。**不要闷头干完再补记录。**

> **改代码的人注意**：动过校验器/构建器/解析器后，**推送前必须先跑它的回归测试**（`npm test`，或 `node workbench/index/test-validate.mjs`）。
> 本地干净数据走不到的分支，只有夹具与 CI 能覆盖（见 KB-2026-0003）。

## 四条铁律（复述，违反即返工）
1. Markdown 是唯一真相源；sqlite/看板/UI 只是派生视图，禁止产生只存在于那里的信息。
2. `00-inbox/` append-only，永不改写；条目正文必须原样保留 `## 原始输入` + sha256。
3. 没有证据不算完成：命令 + 退出码 + 原始输出路径 + 产物 sha256 + 行号引用；**编程 agent 的自述不是证据**。
4. 先验收标准，后实现：进 `executing` 前 PLAN 与 ACC 必须同时存在。

## 意图 → 标准动作
| 用户说 | 你的动作 |
|---|---|
| "记一下 / 有个想法" | 写 `00-inbox/`（原样，不整理），文件名带时间与摘要 |
| "清洗 inbox" | 逐条 → `10-items/WB-YYYY-NNNN-*.md`（填 frontmatter、事实/假设/待验证、澄清问题），回链 raw，原文件不动 |
| "这需求值得做吗 / 初筛" | 填 `triage`：七维度各给一句理由 + verdict 六选一 + open_questions；先查重复（`links.duplicates/related`）|
| "调研 X" | `20-research/RS-*.md`：结论先行，来源清单，严格区分已证实/推断/待验证；能实验就实验 |
| "出方案 / 怎么选" | `30-decisions/ADR-*.md`：≥2 备选、推荐理由、**被放弃方案理由**、风险、**重估触发条件**；状态 proposed，**等人批** |
| "出计划" | `40-plans/PLAN-*.md` + 同批产出 `40-plans/ACC-*.md`（验收先于实现）|
| "派活 / 派给 agent" | `50-exec/EX-*.md` 写自包含任务包（背景/目标/写域/验收/自证），再用 `node workbench/bin/dispatch.mjs --task workbench/50-exec/tasks/T-XXX.md --tool claude|codex|opencode|zcode|custom --cwd <仓库>` 派发（工具无关；同一工作流复用会话，原始输出落 `50-exec/artifacts/dispatch/`）；结果与日志回填 |
| "给我看看 / 可视化" | **给可访问入口，不给截图**：必须包含 ①可直接打开的文件路径 ②需要 URL 时用 `workbench\start-server.cmd`（或 `python -m http.server 8799 --directory workbench`）并给出 http://127.0.0.1:8799/… 。**截图不算交付**（ADR-0005）。 |
| "验收 / 过没过" | `60-verify/VR-*.md`：逐条对照 ACC，证据到行号，关键命令自己复跑；**执行者不得自验收** |
| "沉淀 / 复盘" | `70-knowledge/KB-*.md`，条目转 `80-archive/` |
| "找找以前有没有做过" | 先 `rg` 全文 + frontmatter 过滤，再查 `index/workbench.sqlite`（若存在）；命中写进 `links` |

## 每次写入后必做
1. 更新 frontmatter 的 `updated` 与 `status`；
2. `log/YYYY-MM.md` 追加一行：`时间 | ID | 旧→新 | 触发者 | 依据文件`；
3. 有 `index/` 生成脚本时刷新 `index/DASHBOARD.md` 与 sqlite；
4. 回复用户时：**结论先行 + 文件路径 + 下一步该说的一句话**。

## 绝对禁止
- 改写/删除 `00-inbox/` 内容；
- 只给分数或"综合评分"而不写理由；
- 声称"完成/通过"却没有证据；
- 自己执行自己验收；
- 跳过 `approval` 门禁（正式立项、路线变更、范围扩大、删除/生产操作、合并发布、改验收标准）；
- 一次改多个文件却不说明写域。
