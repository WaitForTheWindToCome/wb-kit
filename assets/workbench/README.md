# Workbench ｜ AI 技术管理与研发决策工作台

**一句话**：一个本地 Markdown 档案库 + 一份规范（`SPEC.md`）+ 一个 agent 技能；写入全部由 AI 完成，人只审批和阅读。

## 谁来做什么

| 角色 | 职责 |
|---|---|
| 你（人） | 随手丢想法进 `00-inbox/`；在门禁上审批（§7）；阅读 `index/DASHBOARD.md` 或编辑器 |
| AI agent（DSH / Claude Code） | 清洗、分类、去重、评估、调研、写方案与计划、派发任务、回收证据、独立验收、更新索引 |
| SQLite / 看板 / 编辑器 | **只读**。它们是 Markdown 的派生视图，随时可删 |

## 30 秒上手

1. 丢一句话进 `00-inbox/`（文件名 `YYYY-MM-DD-HHmm-类型-摘要.md`，内容原样粘贴，不用整理）。
2. 对 AI 说：**"清洗 inbox"** → 它会把内容结构化进 `10-items/`，并给出初筛结论与理由。
3. 对 AI 说：**"对 WB-2026-0001 做调研"** → `20-research/` 出报告（含来源与不确定性）。
4. 说 **"出方案"** → `30-decisions/` 出 ADR（含被放弃方案与重估条件），**等你审批**。
5. 说 **"出计划和验收标准"** → `40-plans/` 出 PLAN + ACC，**先定验收再开工**。
6. 说 **"派给 Claude Code"** → `50-exec/` 出任务包与执行记录。
7. 说 **"独立验收"** → `60-verify/` 逐条对照 ACC 出结论（**不接受"agent 说完成了"**）。
8. 说 **"沉淀"** → `70-knowledge/` 写复盘与可复用结论，条目进 `80-archive/`。

## 目录速查

```
00-inbox/     原始输入（append-only，永不改写）
10-items/     结构化条目（一个事项一个文件）
20-research/  调研报告（来源 + 已证实/推断/待验证）
30-decisions/ 决策记录 ADR（批准后不可改）
40-plans/     开发计划 PLAN + 验收计划 ACC
50-exec/      派发与执行记录（含 artifacts/ 原始输出）
60-verify/    独立验收记录
70-knowledge/ 可复用结论与复盘
80-archive/   终止态
projects/     项目注册表（软件 / 人生 / 考试同构）
templates/    模板
index/        派生索引（可删可重建）
log/          变更日志（按月）
```

**规则全文见 `SPEC.md`——它是唯一权威。**
